## ขั้นที่ 1: ติดตั้งฐานข้อมูลบน Supabase

### 1.1 สร้างโปรเจกต์
1. เข้า <https://supabase.com/dashboard> แล้วล็อกอิน (ใช้บัญชี GitHub ได้)
2. กด **New project**
   - **Name:** `local-market-rent`
   - **Database Password:** ตั้งรหัสที่เดายาก แล้ว **จดเก็บไว้**
   - **Region:** `Southeast Asia (Singapore)`
3. กด **Create new project** แล้วรอประมาณ 1–2 นาที

### 1.2 รันโครงสร้างตาราง
1. เมนูซ้าย → **SQL Editor** → **New query**
2. เปิดไฟล์ `supabase/migrations/20261017000100_init_schema.sql` คัดลอกทั้งหมดไปวาง แล้วกด **Run**
3. ต้องขึ้น `Success. No rows returned`

### 1.3 ใส่ข้อมูลตั้งต้น
1. **New query** อีกครั้ง
2. คัดลอกไฟล์ `supabase/seed.sql` ทั้งหมดไปวาง แล้วกด **Run** (ถ้าเผลอรันซ้ำก็ไม่สร้างข้อมูลซ้ำ)
3. ช่องผลลัพธ์ต้องแสดงตาราง 3 แถว คือ ตลาดเช้า 40 / ตลาดเย็น 38 / อาคาร OTOP 18 (คำสั่งสุดท้ายในไฟล์เป็นคำสั่งตรวจผล)

> ⚠️ ต้องรันข้อ 1.2 ให้ผ่านก่อน แล้วค่อยรัน seed และอย่าไฮไลต์โค้ดไว้แค่บางส่วนตอนกด Run เพราะ Supabase จะรันเฉพาะส่วนที่ไฮไลต์
>
> `seed.sql` ไม่ได้สร้างตารางใดเลย จึงไม่ควรมีหน้าต่าง **"Potential issue detected"** เรื่อง RLS ขึ้นมา ถ้ามีขึ้น แปลว่ากำลังใช้ไฟล์ seed รุ่นเก่า (ที่ใช้ตารางชั่วคราว `seed_spec`) ให้กด **Cancel** แล้วคัดลอกไฟล์รุ่นล่าสุดมาใช้แทน

### 1.4 ตรวจผล
รันคำสั่งนี้ใน SQL Editor:

```sql
select m.market_name, count(s.*) as units
from markets m
join zones  z using (market_id)
join stalls s using (zone_id)
group by m.market_id, m.market_name
order by m.market_id;
```

ผลที่ถูกต้อง:

| market_name | units |
|---|---|
| ตลาดเช้า | 40 |
| ตลาดเย็น | 38 |
| อาคาร OTOP | 18 |

### 1.5 สร้างแอดมินคนแรก
1. เมนูซ้าย → **Authentication** → **Users** → **Add user** → **Create new user**
   - ใส่อีเมลและรหัสผ่าน แล้วติ๊ก **Auto Confirm User**
2. คัดลอก **User UID** ของผู้ใช้ที่เพิ่งสร้าง
3. รันใน SQL Editor โดย **แก้ค่า 3 ค่าในบรรทัด values ให้เป็นของจริงทั้งหมด** (ตัวอย่างข้างล่างเป็นค่าสมมติ):

```sql
insert into public.users (user_id, username, full_name, role, email)
values (
  '3f2a6c1e-0000-0000-0000-000000000000',  -- ← วาง User UID ที่คัดลอกมา
  'admin',
  'สมชาย ใจดี',                            -- ← ชื่อ-นามสกุลจริง (แสดงในแถบเมนู)
  'admin',
  'admin@example.com'                      -- ← อีเมลเดียวกับที่ใช้ login
);
```

ถ้าเคยใส่ไปแล้วและชื่อขึ้นผิด แก้ได้ด้วย:

```sql
update public.users
set full_name = 'สมชาย ใจดี', email = 'admin@example.com'   -- ← แก้เป็นของจริง
where username = 'admin';
```

### สิ่งที่ระบบทำให้อัตโนมัติ
| เรื่อง | การทำงาน |
|---|---|
| เลขแผง | ไม่ใส่รหัสตอนเพิ่มแผง ระบบจะต่อเลขจากเลขสุดท้ายในโซนให้ เช่น `A011` |
| เลขสัญญา | `CT-2569-0001` นับใหม่ทุกปี พ.ศ. |
| เลขใบแจ้งหนี้ | `INV-256910-0001` ตามรอบบิล นับใหม่ทุกรอบ |
| เลขใบเสร็จ | `RC-256910-0001` ตามเดือนที่ออก นับใหม่ทุกเดือน |
| กันเลขซ้ำ | ล็อกระหว่างออกเลข หลายคนกดพร้อมกันก็ไม่ได้เลขซ้ำ และแก้เลขที่ออกแล้วผ่านเว็บไม่ได้ |
| สถานะแผง | มีคำขอเช่า → **จอง**, อนุมัติ → **เช่า**, ไม่อนุมัติ/ยกเลิก/สิ้นสุด → **ว่าง** ส่วนเจ้าหน้าที่ตั้งเองได้แค่ ว่าง ↔ ซ่อมบำรุง |
| ตรวจแผงว่าง | จองหรือทำสัญญาบนแผงที่ไม่ว่างไม่ได้ (ยกเว้นต่ออายุสัญญาของผู้เช่าคนเดิม) และแผงหนึ่งมีคำขอรออนุมัติได้ครั้งละ 1 รายการ |
| ลำดับสถานะสัญญา | รออนุมัติ → ใช้งาน / ไม่อนุมัติ / ยกเลิก · ใช้งาน → สิ้นสุด / ยกเลิก · ที่เหลือเปลี่ยนต่อไม่ได้ |
| คำขอเช่าของผู้เช่า | ผู้เช่าเลือกได้แค่แผงกับวันที่ ระบบกำหนดเอง: ผู้เช่า = ตัวเอง, สถานะ = รออนุมัติ, ค่าเช่า = ตามแผง |
| แจ้งชำระ | ผู้เช่าแจ้งชำระได้เฉพาะบิลของตัวเองที่ **รอชำระ** สถานะเริ่มต้นเป็น **รอตรวจสอบ** เสมอ |
| ผู้ตรวจ/ผู้ออก | `created_by`, `issued_by`, `verified_by`, `verified_at` เติมให้อัตโนมัติจากผู้ที่ login อยู่ |
| วันที่ | `payment_date`, `receipt_date`, `reading_date` ใช้วันที่ตามเวลาไทย (ฐานข้อมูลใช้เวลา UTC) |
| ปิดสัญญาหมดอายุ | เจ้าหน้าที่กดปุ่มเอง ซึ่งเรียก `expire_contracts()` เพื่อเปลี่ยนสัญญาที่เลยวันสิ้นสุดเป็น **สิ้นสุด** และคืนแผงเป็น **ว่าง** |

### สิทธิ์ตามบทบาท (RLS)
| ข้อมูล | admin | staff | manager | ผู้เช่า (LINE) |
|---|---|---|---|---|
| ผู้ใช้ระบบ | จัดการ | ดูของตัวเอง | ดูของตัวเอง | – |
| ตลาด/โซน/อัตราน้ำไฟ/ค่าธรรมเนียม | จัดการ | ดู | ดู | ดู |
| แผง | จัดการ | จัดการ | ดู | ดู |
| ผู้เช่า | จัดการ | จัดการ | ดู | ดู/แก้ของตัวเอง (ยกเว้นสถานะ, บัญชี LINE) |
| สัญญา | จัดการ | จัดการ + อนุมัติ | ดู | ดูของตัวเอง + ขอเช่าแผงว่าง + ยกเลิกคำขอ |

| การชำระเงิน | จัดการ | ตรวจสลิป | ดู | แจ้งชำระ + ดูของตัวเอง |

- **ลบข้อมูล:** เฉพาะ admin เท่านั้น เอกสารการเงินให้ใช้วิธี "ยกเลิก" แทน
- **ยังไม่ login (anon):** เข้าถึงตารางไม่ได้เลย
- **บัญชีที่ถูกระงับ** (`status = 'inactive'`): มองไม่เห็นข้อมูลใดเลยทันที

### หมายเหตุสำหรับตอนทำหน้าเว็บ
- **ตาราง `tenants` ห้ามใช้ `select('*')`** เพราะคอลัมน์ `id_card` ถูกซ่อนไว้ ต้องระบุคอลัมน์เอง เช่น
  `supabase.from('tenants').select('tenant_id, full_name, phone, business_name, status')`
- ดูเลขบัตรประชาชน: `supabase.rpc('get_tenant_id_card', { p_tenant_id: 1 })`
- ปุ่มปิดสัญญาหมดอายุ: `supabase.rpc('expire_contracts')` คืนค่าจำนวนสัญญาที่ปิด

### แก้ปัญหา: หน้าภาพรวมไม่แสดงตลาด
ถ้า login ได้แต่หน้าภาพรวมขึ้นว่า "ไม่พบข้อมูลตลาดที่บัญชีนี้มองเห็น" ให้รันคำสั่งนี้ใน SQL Editor

```sql
-- ตรวจปัญหาหน้าภาพรวมไม่แสดงตลาด (อ่านอย่างเดียว ไม่แก้ข้อมูล)
select set_config('request.jwt.claims',
  json_build_object('sub', (select user_id from public.users where role = 'admin' order by created_at limit 1),
                    'role', 'authenticated')::text, true);

select
  (select count(*) from public.markets) as markets_in_db,
  (select count(*) from public.stalls)  as stalls_in_db,
  auth.uid()                            as admin_uid,
  private.current_user_role()           as role_seen_by_rls,
  private.is_app_user()                 as rls_allows_read;
```

| ผลที่ได้ | สาเหตุ | วิธีแก้ |
|---|---|---|
| `markets_in_db = 0` | ยังไม่มีข้อมูลตั้งต้น | รัน `supabase/seed.sql` ทั้งไฟล์อีกครั้ง (ทำตามข้อ 1.3) |
| `role_seen_by_rls` ว่าง | แถวใน `users` ไม่ตรงกับบัญชี หรือ `status` ไม่ใช่ `active` | ตรวจ `select * from users;` ว่า `user_id` ตรงกับ User UID และ `status = 'active'` |
| ได้ `3, 96, ..., admin, true` | ฐานข้อมูลถูกต้อง | ตรวจว่า `web/.env` ชี้ไปที่โปรเจกต์ Supabase เดียวกัน แล้วกดรีเฟรชหน้าเว็บ |

### 3.4 สิ่งที่มีในขั้นนี้
- **หน้า login เจ้าหน้าที่** (`/login`): ใช้อีเมล + รหัสผ่าน (Supabase Auth) ถ้ารหัสผิดจะขึ้นข้อความภาษาไทย
- **ตรวจบทบาท:** หลัง login จะอ่าน `users` ของตัวเอง ถ้าไม่มีแถว (เช่น บัญชีผู้เช่า) จะขึ้นว่า "ไม่ใช่บัญชีเจ้าหน้าที่" ถ้า `status = inactive` จะขึ้นว่า "ถูกระงับ"

- **ภาพรวม** (`/admin`): ผังแผงทุกตลาด ระบายสีตามสถานะจริง (ว่าง / จอง / เช่า / ซ่อมบำรุง ซึ่งเป็นลายเส้นทแยง) พร้อมจำนวนแต่ละสถานะ ดูรายละเอียดผังและหน้าต่างข้อมูลแผงที่ข้อ 3.6
- **เมนูอื่น** ตอนนี้ขึ้นว่า "จะทำในขั้นที่ X"
- **ฝั่งผู้เช่า** (`/liff`): ยังเป็นแค่โครง จะทำในขั้นที่ 8
- **ใช้บนมือถือได้:** เมนูแบบเลื่อนออก ส่วนผังเลื่อนซ้าย-ขวาได้ภายในกรอบผัง ตัวหน้าเว็บไม่ล้นจอตั้งแต่ 320px
- **ตัวช่วยกลาง** ไว้ใช้ในขั้นต่อไป: `formatBaht()`, `formatDate()` (พ.ศ.), `formatPeriod('2026-10')` → "ต.ค. 2569", `maskIdCard()`, `label(STALL_STATUS, 'vacant')` → "ว่าง", `thaiError(error)`

### 3.6 ผังพื้นที่และหน้าต่างข้อมูลแผง
**ผังพื้นที่ตลาดเย็นและอาคาร OTOP** วางตามภาพผังจริง:

```
          ┌── แผงเช่ารายปี: อาคาร OTOP โซน A (10 ห้อง, ช่องสูง) ──┐
 ┌──────┐ ┌──────────┐
 │ตลาดเย็น│ │ ตลาดเย็น  │   แผงเช่ารายเดือน
 │โซน A  │ │ โซน B     │
 │ 2×4   │ │ 6×5       │
 └──────┘ └──────────┘
          └── แผงเช่ารายปี: อาคาร OTOP โซน B (8 ห้อง, ช่องกว้าง) ───┘
```

- **ตลาดเช้า:** แสดงแบบโซนละหนึ่งแถว แถวละ 10 แผง (ผังเดิม)
- **ตำแหน่งและรูปทรงของแต่ละโซน:** กำหนดใน `web/src/lib/siteLayouts.js` ส่วนจำนวนช่องอ่านจากฐานข้อมูล เพิ่ม/ลบแผงแล้วผังขยาย/หดเอง
- **โซนที่ไม่มีใน `siteLayouts.js`** (เช่น เพิ่มโซนใหม่ภายหลัง): แสดงต่อท้ายเป็นแถวทั่วไปอัตโนมัติ ไม่หายไป
- **กดช่องใดก็ได้** จะเปิดหน้าต่างข้อมูลแผงพร้อมเบลอพื้นหลัง แสดงข้อมูลแผง, ผู้เช่าและสัญญา (หรือคำขอเช่าที่รออนุมัติ) และยอดค้างชำระ ปิดได้ด้วยปุ่มปิด, Esc หรือคลิกนอกหน้าต่าง
- **ปุ่มจัดการ:**

| ปุ่ม | ใครเห็น | เงื่อนไข |
|---|---|---|
| + เพิ่มแผง (ที่หัวโซน) | admin, staff | แผงใหม่ใช้ค่าเดียวกับแผงล่าสุดในโซน และได้รหัสถัดไปอัตโนมัติ |
| ตั้งเป็นซ่อมบำรุง / เลิกซ่อมบำรุง | admin, staff | เฉพาะแผงที่ว่างหรือซ่อมบำรุง (แผงที่เช่า/จองอยู่ เปลี่ยนตามสัญญา) |
| ลบแผงนี้ | admin | เฉพาะแผงที่ว่าง/ซ่อมบำรุง ต้องกดยืนยัน และถ้าแผงเคยมีสัญญาหรือจดมิเตอร์ ฐานข้อมูลจะไม่ยอมให้ลบ |

### 4.2 Deploy Edge Function `admin-users`
หน้า "ผู้ใช้ระบบ" ใช้ฟังก์ชันนี้สร้างบัญชีเจ้าหน้าที่และตั้งรหัสผ่านใหม่ (ต้องใช้ secret key ซึ่งห้ามอยู่ในหน้าเว็บ จึงทำบนเซิร์ฟเวอร์)

**วิธีที่ 1 ผ่าน Dashboard (ไม่ต้องติดตั้งอะไร)**
1. เมนูซ้าย **Edge Functions** → **Deploy a new function** → **Via Editor**
2. ลบโค้ดตัวอย่างออก แล้ววางไฟล์ `supabase/functions/admin-users/index.ts` ทั้งไฟล์
3. **ก่อนกด Deploy ให้ตั้งชื่อฟังก์ชันเป็น `admin-users`** — ถ้าไม่ตั้ง ระบบจะตั้งชื่อสุ่มให้ (เช่น `smart-task`) และ**เปลี่ยนชื่อทีหลังไม่ได้** (ช่อง Name ใน Settings เปลี่ยนแค่ชื่อที่แสดง ส่วนที่อยู่ URL คงเดิม)
4. กด **Deploy function** แล้วรอข้อความสำเร็จ
5. **ตรวจที่อยู่ใต้ชื่อฟังก์ชัน ต้องลงท้ายด้วย `/functions/v1/admin-users`** ถ้าเป็นชื่ออื่น ให้ deploy ใหม่ (แล้วลบฟังก์ชันชื่อสุ่มทิ้ง)
6. แท็บ **Settings** → ปิด **Verify JWT with legacy secret** (ตามที่หน้า Dashboard แนะนำ) → **Save changes**

**วิธีที่ 2 ผ่าน Supabase CLI** (ถ้าติดตั้งไว้แล้ว)
```bash
supabase functions deploy admin-users --no-verify-jwt --project-ref <project-ref>
```

- **ไม่ต้องตั้ง secret เพิ่ม:** Supabase ใส่ `SUPABASE_URL` และ `SUPABASE_SECRET_KEYS` ให้ Edge Function อัตโนมัติ (ถ้าไม่มี ฟังก์ชันจะใช้ `SUPABASE_SERVICE_ROLE_KEY` แทน)
- **ทำไมปิด Verify JWT ได้:** ตัวเลือกนี้รับเฉพาะ token ที่เซ็นด้วย legacy secret ส่วนฟังก์ชันของเราตรวจเองทุกครั้งว่าผู้เรียก login แล้วและเป็น admin ที่ใช้งานอยู่

### 4.4 ทดลองกับ Supabase จริง (แนะนำให้ทำตามลำดับ)
1. **ผู้ใช้ระบบ** → **+ เพิ่มผู้ใช้** → สร้างบัญชีบทบาท "เจ้าหน้าที่" → หน้าต่างสรุปจะแสดงอีเมลและรหัสผ่าน
2. เปิดหน้าต่างไม่ระบุตัวตน (Incognito) แล้ว login ด้วยบัญชีนั้น → ต้องไม่เห็นเมนู "ผู้ใช้ระบบ"
3. **ผู้เช่า** → **+ เพิ่มผู้เช่า** → กดดู "แสดงเลขบัตร" ในหน้าต่างผู้เช่า

## ขั้นที่ 5: คำขอและสัญญาเช่า

### 5.1 รัน migration 005
1. SQL Editor → **New query**
2. วางไฟล์ `supabase/migrations/20261018000500_contract_note.sql` ทั้งไฟล์ แล้วกด **Run**
3. ต้องขึ้น `Success. No rows returned` (ข้อความ NOTICE ว่า constraint does not exist, skipping เป็นเรื่องปกติ)

ไฟล์นี้ทำ 2 อย่าง (ผู้ใช้อนุมัติแล้วทั้งสองข้อ) และไม่แตะข้อมูลเดิม
- **เพิ่มคอลัมน์ `contracts.note`** (ข้อความ เว้นว่างได้ ไม่เกิน 500 ตัวอักษร): เหตุผลที่ไม่อนุมัติ/ยกเลิก หรือข้อความจากผู้เช่าตอนส่งคำขอ
- **ต่ออายุซ้ำได้หลังคำขอต่ออายุถูกไม่อนุมัติ/ยกเลิก:** เดิม `renewed_from_id` ห้ามซ้ำทั้งคอลัมน์ ทำให้สัญญาที่คำขอต่ออายุถูกปฏิเสธไปแล้วต่ออายุไม่ได้อีกเลย ตอนนี้นับเฉพาะสัญญาต่ออายุที่ยังมีผล (รออนุมัติ/ใช้งาน/สิ้นสุด)

ตรวจผล:
```sql
select
  (select count(*) from information_schema.columns
    where table_name = 'contracts' and column_name = 'note') as note_column,                 -- ต้องได้ 1
  (select count(*) from pg_indexes where indexname = 'contracts_one_renewal_per_contract') as renewal_rule; -- ต้องได้ 1
```

### 5.3 ทดลองกับ Supabase จริง
1. **ภาพรวม** → กดแผงว่าง → **ทำสัญญาเช่า** → เลือกผู้เช่า → ดูว่าวันสิ้นสุดตั้งต้นถูก (ตลาด 1 ปี / OTOP 3 ปี) → **ทำสัญญา** → แผงบนผังเปลี่ยนเป็น "เช่า"
2. **คำขอและสัญญาเช่า** → แท็บสัญญาใช้งาน → เปิดสัญญาที่เพิ่งทำ → **ต่ออายุ…** → ส่งคำขอ → แท็บคำขอรออนุมัติ → **อนุมัติ…**
3. ลอง **ไม่อนุมัติ** คำขอต่ออายุพร้อมเหตุผล แล้วต่ออายุสัญญาเดิมใหม่อีกครั้ง (ต้องทำได้ เพราะ migration 005)
4. **ยกเลิกสัญญา** พร้อมเหตุผล → แผงกลับเป็น "ว่าง" (ถ้าไม่มีสัญญาอื่นที่ใช้งานอยู่)

จะเห็น bucket `slips` (Private) ที่ Dashboard → **Storage** ด้วย

**ถ้าเคยใส่ข้อมูลจำลองไว้ก่อนแล้ว:** ข้อมูลเดิมใช้ต่อได้ แต่ถ้าอยากได้ตัวอย่างใหม่ของขั้นนี้ (จ่ายบางส่วน, ใบเสร็จที่ยกเลิก) ให้รัน `demo_data_remove.sql` แล้วรัน `demo_data.sql` ใหม่

### 7.3 ตั้งพร้อมเพย์ของตลาด (ผู้ดูแลระบบ)
**ตลาดและอัตราค่าบริการ** → เลือกตลาด → หัวข้อ "รับชำระผ่านพร้อมเพย์" → **ตั้งพร้อมเพย์**
- ใส่เบอร์มือถือ 10 หลัก หรือเลขผู้เสียภาษี 13 หลักของหน่วยงาน + ชื่อบัญชี
- **ก่อนบันทึก ให้สแกน QR ตัวอย่างด้วยแอปธนาคาร** ดูว่าชื่อผู้รับตรงกับบัญชีของตลาด (ไม่ต้องโอนจริง) ถ้าเลขผิด เงินของผู้เช่าจะเข้าบัญชีคนอื่น
- ตลาดที่ยังไม่ตั้ง ใบแจ้งหนี้จะไม่มี QR (รับเงินสด/บันทึกการโอนที่สำนักงานได้ตามปกติ)

### 7.4 ทดลองกับ Supabase จริง
1. **ใบแจ้งหนี้** → เปิดใบที่รอชำระ → เห็น QR พร้อมยอดคงค้าง → **พิมพ์ใบแจ้งหนี้** (แท็บใหม่ กด "พิมพ์ / บันทึก PDF")
2. ในหน้าต่างเดิม → **รับชำระ** → ใส่ยอดน้อยกว่ายอดค้าง (ลองแบ่งจ่าย) เลือก "โอนเงิน" แนบรูปสลิป → **รับชำระและออกใบเสร็จ** → กด **พิมพ์ใบเสร็จ**
3. รับส่วนที่เหลือเป็นเงินสด → ใบแจ้งหนี้เป็น "ชำระแล้ว" เอง
4. **ตรวจการชำระเงิน** (ถ้าใส่ข้อมูลจำลอง จะมีสลิปรอตรวจ 2 รายการ) → เปิดรายการ → **ผ่าน — ออกใบเสร็จ** / **ไม่ผ่าน…** พร้อมเหตุผล
5. (ผู้ดูแลระบบ) แท็บ **ตรวจแล้ว** → เปิดรายการ → **ยกเลิกใบเสร็จ…** → ใบแจ้งหนี้กลับเป็นรอชำระ และใบเสร็จที่พิมพ์ซ้ำจะมีตรา "ยกเลิก"

**กติกาที่ฐานข้อมูลบังคับ** (migration 007)
- **แบ่งจ่ายได้** แต่ละครั้งได้ใบเสร็จของตัวเอง · ยอดที่ตรวจแล้วรวมกัน**เกินยอดใบแจ้งหนี้ไม่ได้** (กันกดพร้อมกันหลายคนด้วย)

- ตั้งสถานะใบแจ้งหนี้เองให้ไม่ตรงกับเงินที่รับจริงไม่ได้ · **แก้ยอดในใบแจ้งหนี้ไม่ได้** (ยกเลิกแล้วออกใหม่) แต่เลื่อนวันครบกำหนดได้

- การชำระที่ตรวจแล้วแก้ยอด/วันที่/วิธีชำระไม่ได้ · "ไม่ผ่าน" แล้วจบ (ผู้เช่าแจ้งใหม่) · ใบเสร็จแก้หรือลบไม่ได้ ยกเลิกได้ทางเดียวคือผู้ดูแลระบบกด "ยกเลิกใบเสร็จ" พร้อมเหตุผล (บันทึกเลขใบ เหตุผล ผู้ยกเลิก วันที่)
- วันที่ชำระล่วงหน้าไม่ได้
- **สลิป:** เก็บใน bucket `slips` แบบส่วนตัว ที่ `<tenant_id>/<invoice_id>/…` รูป JPG/PNG/WebP ไม่เกิน 5 MB · ผู้เช่าอัปโหลด/เห็นได้เฉพาะของตัวเองและเฉพาะใบแจ้งหนี้ของตัวเอง (ใช้ในขั้นที่ 8) · เจ้าหน้าที่ทุกบทบาทเห็นทั้งหมด admin/staff อัปโหลดแทนได้ · ลบได้เฉพาะ admin · เปิดดูผ่านลิงก์ชั่วคราว 10 นาที

1. **Create a new provider** → ตั้งชื่อหน่วยงาน เช่น "เทศบาล…" (มีอยู่แล้วข้ามได้)
2. ใน provider → **Create a new channel** → **LINE Login**
   - Region: Thailand · Channel name: เช่น "แผงค้าตลาด" (**ห้ามมีคำว่า LINE**) · Description · ไอคอน: ใช้ไฟล์ `docs/brand/line-channel-icon.png`
   - **App types: เลือก Web app** · Email address ของผู้ดูแล → ยอมรับเงื่อนไข → **Create**
3. แท็บ **Basic settings** → จด **Channel ID** (ตัวเลข 10 หลัก ใช้ในข้อ 8.5) — *ไม่ใช่* Channel secret
4. แท็บ **LIFF** → **Add**
   - LIFF app name: เช่น "ผู้เช่าแผง" · **Size: Full**
   - **Endpoint URL: `https://<ที่อยู่ Vercel>/liff`** เช่น `https://local-market-rent.vercel.app/liff`
   - **Scopes: ติ๊ก `openid` และ `profile`** (ไม่ต้องติ๊ก chat_message.write)
   - Add friend option: **Off** (ยังไม่ใช้ LINE OA) · Scan QR: ไม่ต้องเปิด → **Add**
5. จด **LIFF ID** (รูปแบบ `2001234567-AbCdEfGh`) และ LIFF URL `https://liff.line.me/<LIFF ID>`

> LINE แนะนำให้แอปใหม่ทำเป็น LINE MINI App แต่ LIFF บนช่องทาง LINE Login ยังใช้ได้ และตั้งค่าน้อยกว่า ถ้าย้ายภายหลังแค่เปลี่ยน LIFF ID กับ Channel ID

### 8.5 Deploy Edge Function `line-auth`
เหมือนข้อ 4.2 แต่ใช้ไฟล์ `supabase/functions/line-auth/index.ts`
1. **Edge Functions → Deploy a new function → Via Editor** → วางไฟล์ทั้งไฟล์
2. **ตั้งชื่อเป็น `line-auth` ก่อนกด Deploy** → ตรวจว่าที่อยู่ลงท้ายด้วย `/functions/v1/line-auth`
3. แท็บ **Settings** → ปิด **Verify JWT with legacy secret** → **Save changes** (ผู้เช่ายังไม่ได้ login ตอนเรียกฟังก์ชันนี้ ฟังก์ชันตรวจ ID token กับ LINE เองทุกครั้ง)
4. **Edge Functions → Secrets** (Edge Function Secrets) → **Add new secret**: Name `LINE_CHANNEL_ID` · Value = Channel ID จากข้อ 8.4 ข้อ 3 → **Save**

CLI: `supabase functions deploy line-auth --no-verify-jwt --project-ref <project-ref>` แล้ว `supabase secrets set LINE_CHANNEL_ID=<Channel ID> --project-ref <project-ref>`

### 8.6 ใส่ LIFF ID ในหน้าเว็บ แล้ว deploy ใหม่
1. `web/.env` เพิ่มบรรทัด `VITE_LIFF_ID=<LIFF ID>`
2. Vercel → **Settings → Environment Variables** → เพิ่ม `VITE_LIFF_ID` (Production + Preview)
3. `npx vercel --prod`

LIFF ID ไม่ใช่ความลับ (อยู่ในลิงก์ที่แจกผู้เช่าอยู่แล้ว) · **ห้ามตั้ง `VITE_LIFF_MOCK` ใน Vercel** (เป็นโหมดจำลองสำหรับชุดทดสอบเท่านั้น)

### 8.7 เปิดให้ผู้เช่าทุกคนใช้ (Publish)
ช่องทาง LINE Login ที่สร้างใหม่อยู่ในสถานะ **Developing** ซึ่ง**มีแค่ Admin/Tester ของช่องทางที่เข้าได้** ทดลองเองให้ผ่านก่อน (ข้อ 8.9) แล้วกดสถานะที่หัวช่องทางเปลี่ยนเป็น **Published**

### 8.8 (แนะนำ) ตั้ง rate limit ของ Supabase Auth
ทุกการเข้าระบบครั้งแรกของผู้เช่าผ่าน Edge Function ตัวเดียว และ Supabase จำกัดการออก session ไว้ **30 ครั้ง/5 นาที ต่อ IP**
- **Authentication → Rate Limits → เปิด IP Address Forwarding** → ฟังก์ชันส่ง IP ของผู้เช่าแต่ละคนไปให้ จึงนับแยกรายคน
- ถ้าจะให้ผู้เช่าจำนวนมากสแกนพร้อมกัน (เช่น ประชุมผู้ค้า) เพิ่มค่า **verification requests** ในหน้าเดียวกันได้
- เข้าระบบแล้วไม่ต้องทำซ้ำ (ระบบต่ออายุ session ให้เอง) จึงปกติไม่ถึงขีดจำกัด

### 8.9 ทดลองกับของจริง
ใช้ข้อมูลจำลองได้ (ถ้าใส่ไว้ในข้อ 6.3) เช่น **นางมาลี บุญมา** เลขบัตร `0099000003032` เบอร์ `0812341103`
1. ส่งลิงก์ `https://liff.line.me/<LIFF ID>` เข้าแชตของตัวเองใน LINE บนมือถือ แล้วกดเปิด → กด **อนุญาต**
2. หน้า **ผูกบัญชี LINE กับข้อมูลผู้เช่า** → กรอกเลขบัตร + เบอร์ข้างบน → เข้าหน้าแรก เห็นยอดค้างชำระและแผงที่เช่า
3. **บิล** → เปิดใบที่ต้องชำระ → เห็น QR พร้อมเพย์ (ตลาดต้องตั้งพร้อมเพย์ไว้แล้ว ข้อ 7.3) → แนบรูปสลิปอะไรก็ได้ → **ส่งสลิป**
4. ที่คอมเจ้าหน้าที่: **ตรวจการชำระเงิน** → เห็นสลิปนั้นรอตรวจ → **ผ่าน** → ที่มือถือกลับไปเมนู **บิล** แล้วเปิดใบนั้นอีกครั้ง → มีลิงก์ใบเสร็จ
5. **เช่าแผง** → แตะแผงสีขาว → **ส่งคำขอเช่า** → ที่คอม **คำขอและสัญญาเช่า** เห็นคำขอใหม่ → ที่มือถือหน้าแรกกด **ยกเลิกคำขอ** ได้
6. **ข้อมูลของฉัน** → แก้เบอร์โทร → ที่คอมหน้า **ผู้เช่า** เห็นเบอร์ใหม่
7. หน้า **ผู้เช่า** → เปิดนางมาลี → **ยกเลิกการผูก LINE** → ปิดเปิดลิงก์บนมือถือใหม่ → ต้องกลับไปหน้าผูกบัญชี
8. ลองผูกด้วยเลขบัตรที่ไม่มีในระบบ → ขึ้นว่าไม่พบข้อมูล ให้ติดต่อสำนักงาน (ผู้เช่าใหม่ให้สำนักงานเพิ่มในหน้า **ผู้เช่า** ก่อน แล้วจึงผูก LINE ได้)
9. หน้า **ผู้เช่า** → **ป้าย QR เข้า LINE** → พิมพ์/บันทึก PDF ไปติดที่สำนักงาน

บัญชีผู้เช่าที่เข้าผ่าน LINE จะเห็นใน Supabase → **Authentication → Users** เป็นอีเมล `line_….@line.local` (ไม่มีการส่งอีเมลจริง) ลบได้ไม่กระทบข้อมูลผู้เช่า (ครั้งหน้าที่เปิดจะสร้างให้ใหม่)

### 8.10 สิ่งที่มีในขั้นนี้
| หน้า (ผู้เช่า, มือถือ) | ทำอะไรได้ |
|---|---|
| **ผูกบัญชี** | ครั้งแรกครั้งเดียว: เลขบัตร + เบอร์โทรที่สำนักงานบันทึก (พิมพ์เลขไทยได้) · ไม่พบเลขบัตร → แจ้งให้ติดต่อสำนักงาน (ไม่มีการลงทะเบียนเอง) · เปิดด้วย LINE อีกบัญชีบนเครื่องเดิมจะไม่เห็นข้อมูลของคนก่อน |

| **ผังตลาด** | ช่องมุมโค้ง ไม่มีกรอบดำหนา มีช่องไฟระหว่างช่อง · ทุกโซนใช้ขนาดช่องและระยะห่างเดียวกัน วางบนกริดคอลัมน์เดียวกัน จึงตรงแนวทั้งแนวตั้งและแนวนอน (ห้อง OTOP แถวบน-ล่าง และตลาดเย็นโซน B ตรงคอลัมน์กัน) · แต่ละโซนกำหนดจำนวนช่องต่อแถว (`cols` ใน `siteLayouts.js`) เพิ่มแผงเกินแล้วขึ้นแถวใหม่ตรงคอลัมน์แรก โซนด้านล่างเลื่อนลงให้เอง · ปุ่ม "+ เพิ่มแผง" ย้ายไปอยู่ที่ป้ายโซน |

| เอกสารพิมพ์ | ใบแจ้งหนี้ (มี QR) และใบเสร็จ ขนาด A5 พิมพ์จากเบราว์เซอร์หรือบันทึก PDF | ตามที่ผู้ใช้เลือก · ไม่ต้องมีเซิร์ฟเวอร์สร้าง PDF |

| ช่องทาง LINE | ช่องทาง LINE Login + LIFF app | ยังรองรับและตั้งค่าน้อยที่สุด (LINE แนะนำ LINE MINI App สำหรับแอปใหม่ ย้ายภายหลังได้โดยเปลี่ยน `VITE_LIFF_ID` กับ `LINE_CHANNEL_ID`) |

| ผู้เช่าแก้ข้อมูลเอง | เฉพาะเบอร์โทร ที่อยู่ ชื่อร้าน (ชื่อ เลขบัตร สถานะ บัญชี LINE ให้สำนักงานแก้) | ชื่อและเลขบัตรใช้ยืนยันตัวตนและทำสัญญา |

| ป้าย QR | หน้าพิมพ์ A5 จากหน้า "ผู้เช่า" ใช้ลิงก์ `https://liff.line.me/<LIFF ID>` | ติดที่สำนักงาน/บอร์ดตลาดให้ผู้เช่าสแกน |

### กฎที่ฐานข้อมูลบังคับให้อัตโนมัติ (จากขั้นที่ 1)
- แผงเดียวกันมีสัญญา `active` ที่ช่วงวันที่ทับกันไม่ได้
- อัตราค่าน้ำ/ไฟ `active` ของตลาดเดียวกันมีช่วงวันที่ทับกันไม่ได้ (เปลี่ยนอัตรา = ใส่ `effective_to` ให้อัตราเดิมก่อน)
- สัญญาหนึ่งมีใบแจ้งหนี้ได้รอบละ 1 ใบ (ยกเว้นใบที่ยกเลิกแล้ว)
- แผงหนึ่งจดมิเตอร์แต่ละประเภทได้รอบละ 1 ครั้ง และเลขมิเตอร์ห้ามถอยหลัง
- `unit_used` และ `total_amount` คำนวณให้อัตโนมัติ แก้มือไม่ได้
- การชำระหนึ่งครั้งออกใบเสร็จได้ 1 ใบ
- ลบตลาด/โซน/แผง/ผู้เช่าที่ยังมีข้อมูลผูกอยู่ไม่ได้
